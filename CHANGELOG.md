## 09.03.2026 — Импорт работ: порядок строк как в Excel

Таким образом таблица «Работы по корпусу» в приложении отображает работы строго в том же порядке, в каком они идут в исходном файле Excel.

## 09.03.2026 — initial_executed и ежедневный учёт: единая модель без задвоений

- **Что было сделано:** Уточнена логика работы с объёмами: ручной ввод и импорт обновляют только поле «Уже выполнено (до ежедневного учёта)» в таблице works, а ежедневный календарь всегда пишет/правит только записи в work_progress. В скрипте импорта из Excel при повторном запуске для существующей работы обновляются объём и план, а initial_executed меняется только если по работе ещё нет записей в work_progress; поколоночные данные по дням не добавляются, если по работе уже есть ежедневные записи. Скрипт обратной заливки backfill_work_progress_to_date теперь создаёт одну запись только для работ без initial_executed и без каких‑либо записей в work_progress. Для API календаря и сохранения дневных объёмов добавлена детализация ошибок БД: отдельные подсказки для отсутствующей таблицы work_progress, отсутствующих столбцов initial_executed и date, а также общий текст «Ошибка БД…»; сообщения возвращаются в JSON и показываются на фронтенде без жёстко зашитых SQL‑скриптов.
- **Файлы:** app/blueprints/project/routes.py (обработка ошибок в _work_daily_json и update_daily, хелперы _extract_db_programming_error/_format_db_programming_error), app/templates/buildings/building_graphs.html (alert с текстом ошибки из JSON, обработка ошибок загрузки календаря), scripts/import_works_from_excel.py (обновление существующих работ, защита от задвоения initial_executed и work_progress), scripts/backfill_work_progress_to_date.py (условия пропуска работ с initial_executed или progress), scripts/export_works_to_excel.py (учёт initial_executed при подсчёте выполнения), CHANGELOG.md.
- **Эффект:** Объём выполненных работ считается по единой формуле initial_executed + сумма ежедневных записей без задвоений при повторных импортах, скриптах и в Excel‑выгрузке; администратор при ошибках сразу видит, какой SQL‑скрипт нужно выполнить или что проверить в структуре таблиц.

## 09.03.2026 — Работы и выполнение: безопасный сброс, уникальность и защита от дублей при импорте
