# Таблицы и столбцы для ГПР (план и график работ)

Сводка таблиц и столбцов, которые участвуют в формировании вкладки **«План и график работ»**. По ним можно подготовить листы в Excel и затем загрузить данные в БД.

---

## 1. Сводная таблица фактического выполнения (график работ)

**Таблица в БД:** `schedule_works`

| Столбец в БД       | Тип в PostgreSQL | Описание для Excel |
|--------------------|------------------|--------------------|
| `id`               | SERIAL (PK)      | Не заполнять — генерируется автоматически |
| `project_id`       | INTEGER          | **Обязательно.** ID проекта из таблицы `projects` (например, 9). Один на весь год по объекту. |
| `building_id`      | INTEGER, NULL    | ID корпуса из `buildings` (если работа привязана к корпусу). Можно пусто. |
| `floor_id`         | INTEGER, NULL    | ID этажа из `floors` (если привязка к этажу). Можно пусто. |
| `name`             | TEXT, NULL       | Название работы (например: «Устройство фундамента», «Отделка 1 этажа»). |
| `planned_start`    | DATE, NULL       | Плановая дата начала. Формат в Excel: `YYYY-MM-DD`. |
| `planned_end`      | DATE, NULL       | Плановая дата окончания. Формат: `YYYY-MM-DD`. |
| `fact_start`       | DATE, NULL       | Фактическая дата начала. Формат: `YYYY-MM-DD`. |
| `fact_end`         | DATE, NULL       | Фактическая дата окончания. Формат: `YYYY-MM-DD`. |
| `percent_complete` | FLOAT, NULL      | Процент выполнения 0–100 (число, например 50 или 100). |
| `status`           | VARCHAR(50), NULL| Статус: одно из «Запланировано», «В работе», «Просрочено», «Завершено». |
| `notes`            | TEXT, NULL       | Примечания (текст). |
| `created_at`       | TIMESTAMP        | Не заполнять — по умолчанию подставится текущее время. |

**Справочники (ID подставлять из существующих таблиц):**

- `project_id` — из таблицы `projects` (поле `id`).
- `building_id` — из таблицы `buildings` (поле `id`), корпус должен относиться к этому проекту.
- `floor_id` — из таблицы `floors` (поле `id`), этаж должен относиться к выбранному корпусу.

**Пример заголовков для листа Excel под импорт в `schedule_works` (значения дат условные):**

```
project_id	building_id	floor_id	name	planned_start	planned_end	fact_start	fact_end	percent_complete	status	notes
9			Устройство фундамента	YYYY-MM-DD	YYYY-MM-DD	YYYY-MM-DD		15	В работе	
9			Отделка 1 этажа	YYYY-MM-DD	YYYY-MM-DD			0	Запланировано	
```

Пустые ячейки — NULL. Даты в формате `YYYY-MM-DD`.

## 2. План производства (ГПП) — задачи для Gantt

**Таблица в БД:** `plan_tasks`

| Столбец в БД   | Тип в PostgreSQL | Описание для Excel |
|----------------|------------------|--------------------|
| `id`           | SERIAL (PK)      | Не заполнять — генерируется автоматически. Нужен для ссылок по `dependency_id`. |
| `project_id`   | INTEGER, NULL     | **Обязательно.** ID проекта из `projects`. |
| `name`         | VARCHAR(500), NULL | Название задачи (например: «Подготовка площадки», «Монтаж каркаса»). |
| `start_date`   | DATE, NULL       | Дата начала. Формат: `YYYY-MM-DD`. |
| `end_date`     | DATE, NULL       | Дата окончания. Формат: `YYYY-MM-DD`. |
| `task_type`    | VARCHAR(50), NULL| Тип для цвета в Gantt: «Подготовка», «Демонтаж» или «Монтаж». |
| `dependency_id`| INTEGER, NULL    | ID другой задачи из этой же таблицы `plan_tasks`, после которой идёт данная (связь «зависимость»). Оставить пустым для первых задач. |
| `building_id`  | INTEGER, NULL    | ID корпуса из `buildings`. Можно пусто. |
| `floor_id`     | INTEGER, NULL    | ID этажа из `floors`. Можно пусто. |
| `notes`        | TEXT, NULL       | Примечания. |
| `sort_order`   | INTEGER, NULL    | Порядок отображения (1, 2, 3…). Можно пусто. |
| `created_at`   | TIMESTAMP        | Не заполнять. |

**Важно по `dependency_id`:** заполнять после того, как в таблице уже есть строки с нужными `id`. Обычно сначала загружаете все задачи без зависимостей, смотрите сгенерированные `id` в БД, затем обновляете `dependency_id` у следующих задач (или загружаете вторым проходом).

**Пример заголовков для листа Excel под импорт в `plan_tasks` (значения дат условные):**

```
project_id	name	start_date	end_date	task_type	dependency_id	building_id	floor_id	notes	sort_order
9	Подготовка площадки	YYYY-MM-DD	YYYY-MM-DD	Подготовка				Первый этап	1
9	Демонтаж старых конструкций	YYYY-MM-DD	YYYY-MM-DD	Демонтаж				Зависит от подготовки	2
9	Монтаж каркаса	YYYY-MM-DD	YYYY-MM-DD	Монтаж				После демонтажа	3
```

После загрузки можно вручную в pgAdmin проставить `dependency_id` (например, для «Монтаж каркаса» указать `id` задачи «Демонтаж старых конструкций»).

## Краткая шпаргалка по типам и форматам

| Тип в БД   | В Excel / при импорте |
|------------|------------------------|
| DATE       | `YYYY-MM-DD` (например 2024-12-31) |
| INTEGER    | Целое число (id из справочников) |
| FLOAT      | Число с точкой при необходимости (например 75.5 для %) |
| TEXT / VARCHAR | Текст, кавычки при необходимости |
| NULL       | Пустая ячейка или отсутствие значения |

Для импорта на целый год: задайте в Excel `project_id` вашего объекта, заполните строки по месяцам/работам для `schedule_works` и при необходимости — этапы для `plan_tasks`, сохраните в CSV (разделитель табуляция или запятая, кодировка UTF-8) и выполните импорт в выбранном инструменте администрирования PostgreSQL, указав соответствие столбцов файла столбцам таблицы (столбец `id` не импортировать, даты — в формате выше).
