# Импорт сводной по проекту из Excel (работы и ежедневное выполнение)

Структура данных для вкладки «План и график работ» и скрипта импорта.

---

## Таблицы БД (иерархия)

- **Project** → **Building** → **Work** → **WorkProgress**
- **works** — работы по корпусу: название (тип), объём, единица, плановая дата завершения, % выполнения.
- **work_progress** — ежедневное выполнение: по одной записи на (work_id, date) с полем daily_execution (объём за день).

Сводки (итоги по проекту, по корпусам) считаются в представлениях агрегацией, отдельные таблицы под итоги не создаются.

---

## Ожидаемая структура Excel

### Лист «Общая»

- Назначение: сводка по проекту (даты договора, общие итоги).
- Использование: опционально; скрипт импорта только проверяет наличие листа. Данные можно использовать во view для вывода сводного блока (даты, контракт, итоги) — агрегацией из `works` и `work_progress`.

### Листы по корпусам (например «6 корпус», «Корпус 6»)

- Один лист = один корпус. Имя листа сопоставляется с названием корпуса в БД (по точному совпадению, по вхождению «корпус» и части имени, или по цифре в названии листа — «6 корпус» → корпус с «6» в имени). При необходимости маппинг задаётся флагом `--building-sheet "6 корпус:Корпус 6"`.

**Фактическая структура work1.xlsx:** таблица начинается со **строки 30** (заголовки в строке 29). Скрипт ищет строку с текстом «Тип работ» в первых 10 ячейках.

| Колонка | Содержимое              | Пример        |
|---------|-------------------------|---------------|
| 0       | Тип работ (название)    | Демонтажные работы |
| 2       | Объем                   | 732           |
| 3       | ед. изм.                | кв.м, шт.     |
| 4       | Процент                 | 0.68 или 68   |
| 5       | Дата завершения по ГПР   | YYYY-MM-DD    |
| 6       | Выполнение (метка)      | —             |
| 7+      | Даты по дням (datetime)| объём за день |

- **Процент:** в файле может быть долей (0.68); скрипт автоматически переводит в проценты (68).
- **Колонки с 7:** заголовок — дата (datetime или Excel serial). Значение в ячейке — объём за день (daily_execution), пишется в `work_progress`.

Конвертация дат Excel: порядковый номер дня (например 46040) в дату через origin **1899-12-30** (стандарт Windows Excel).

## Шаблон строк для разделов и подразделов (EXCEL_WORKS_TEMPLATE.json)

Чтобы не полагаться только на автоматический поиск заголовков по тексту («Демонтажные работы», «Инженерные системы» и т.п.), скрипт импорта может читать отдельный шаблон по строкам:

- Файл: `docs/EXCEL_WORKS_TEMPLATE.json`
- Назначение: жёстко указать, какие строки Excel являются заголовками разделов, подразделов инженерных систем или служебными строками, которые нужно игнорировать при импорте.

Если файл `EXCEL_WORKS_TEMPLATE.json` отсутствует, скрипт работает по прежней логике: ищет заголовки разделов и подразделов по тексту и наличию/отсутствию объёма.

## Скрипт импорта

```bash
# Файл можно переименовать в work1.xlsx и положить в корень проекта или указать путь.

# Просмотр без записи в БД
python scripts/import_works_from_excel.py work1.xlsx --project-id 9 --dry-run

# Импорт
python scripts/import_works_from_excel.py work1.xlsx --project-id 9

# Маппинг лист → корпус в БД
python scripts/import_works_from_excel.py work1.xlsx --project-id 9 --building-sheet "6 корпус:Корпус 6" --building-sheet "7 корпус:Корпус 7"
```

Требования: в проекте должны существовать корпуса (таблица `buildings`), имена листов должны совпадать или маппиться на эти названия.

## Примеры view и шаблонов (Flask)

### 1. Сводка по проекту (как лист «Общая»)

В роуте дашборда проекта или отдельной страницы:

- Агрегаты по `Work` и `WorkProgress`: сумма объёмов по проекту/корпусам, сумма выполненного за период, процент выполнения. Даты и договор — из `Project` (start_date, end_date, contract_number).
- Передать в шаблон: `project`, `works_by_building` (список корпусов с работами и итогами), `totals` (общие суммы).

### 2. Детализация по корпусу

- Роут вида `/project/<id>/building/<building_id>/works` (или раздел на дашборде корпуса).
- Выборка: `Work.query.filter_by(project_id=..., building_id=...).order_by(Work.sort_order)`.
- Для каждой работы подтянуть `work.progress` (или запрос к `WorkProgress` по work_id), сгруппировать по дате.
- Таблица: строки = работы (название, объём, ед., плановая дата, %); колонки = даты; в ячейках — daily_execution (или кумулятива за период). Фильтры: период дат, корпус.

### 3. Шаблон (Bootstrap-таблица)

- Общая сводка: одна таблица с корпусами и итогами (объём план, объём факт, %).
- Детальная таблица по корпусу: `<table class="table table-bordered">`, заголовок — даты (например через цикл по диапазону), строки — работы, ячейки — значения из `WorkProgress` по (work_id, date). Gantt-интеграция: можно выводить те же данные в виде полос (например через существующий блок с Mermaid или отдельный компонент по датам).

### 4. Конвертация даты Excel в Python (для своих скриптов)

```python
from datetime import date, timedelta
EXCEL_ORIGIN = date(1899, 12, 30)

def excel_serial_to_date(serial):
    if serial is None:
        return None
    return EXCEL_ORIGIN + timedelta(days=int(float(serial)))
```
